# Multilingual interface (uz · ru · en)

Languages: **Uzbek `uz` (default for new visitors)**, **Russian `ru`**, **English `en`** (also the fallback for any missing text).
Three independent settings exist and switching one never changes the others:

| Setting | Meaning | Where |
|---|---|---|
| Interface language | menus, buttons, messages, course/lesson titles | selector in the header/sidebar and Profile → `users.ui_language` |
| Translation language | language of word translations, exercise options/answers/hints | Profile → `users.translation_language` (`uz` or `ru`) |
| Learning language | always English | `users.learning_language` |

## Language precedence (client)
signed-in user's saved language → `localStorage['lexi.lang']` → site default (`default_language` setting, `uz` out of the box) → `uz`.
Choosing a language re-renders the current page without reloading the app, saves it on the device and (when signed in) in the profile (`PATCH /api/me {uiLanguage}`).
After sign-in the saved account language is adopted, so it follows the user to another device on the next authenticated load.

## Architecture
* `shared/i18n-core.js` – one engine for server and browser: `{placeholder}` interpolation, plural forms via `Intl.PluralRules`, English fallback, `Intl` date/number formatting.
* `locales/{en,uz,ru}.json` – flat dictionaries with stable keys (`nav.home`, `lesson.check`, `settings…`). Count texts are plural objects (`one/few/many/other` as the language needs).
* `GET /api/i18n/:lang` – the texts, merged with administrator edits stored in `translation_overrides`.
* Server messages are **keys** (`err.*`, `val.*`, `msg.*`, `path.*`) translated at the error boundary using `X-Lang` / the user's language, so API errors and validation messages follow the interface language.
* Content: titles/descriptions of courses, levels, units and lessons use `translations` JSON (interface language); exercise variants and vocabulary translations use the translation language (`vocabulary.translations.ru`, `ru_example`, exercise `translations.ru`). The base columns are English (navigation) / Uzbek (translation-language content).

## Administrator
* **Admin → Translations**: completeness per language, missing texts, search/filter, edit with validation (key must exist, placeholders must match English, no HTML, plural forms, length, encoding), reset to file text, export JSON. Edits are audited (`i18n.update`).
* **Admin → Settings → Languages**: languages offered, default interface language, default translation language.
* Course, level, unit and lesson dialogs have Uzbek/Russian title and description fields; the exercise editor has a Russian version section; the vocabulary dialog has Russian word and example fields.

## Adding or changing texts
1. Add the key to all three `locales/*.json` (the test `tests/api/i18n.test.js` fails if keys, placeholders or plural forms differ, or if code uses a key that does not exist).
2. Use `t('key', {params})` / `n('plural.key', count)` in the client, `req.t(...)` or a key in `HttpError`/`bad()` on the server.

## Not translated (by design)
* Server/CLI log output and `npm` command prompts (English, for operators).
* Audit-log action codes (`course.create`, …) and entity ids.
* Text that an administrator typed: a custom maintenance message, free-text content without a Uzbek/Russian variant, and the English grammar notes in the sample lessons' explanations (they are English-teaching content).
* Names of languages are always shown in their own language (🇺🇿 O‘zbekcha, 🇷🇺 Русский, 🇬🇧 English).
* The language of text-to-speech depends on the browser's installed voices.
