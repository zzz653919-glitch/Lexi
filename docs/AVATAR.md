# Avatar Studio, LEXIO TOKENS and the Avatar Shop

## What it is
* **Avatar Studio** (`/avatar`): a large live preview and options for every part (style, face shape, skin, hairstyle and colour, eyes, eyebrows, mouth, clothes, shoes, hats, glasses, accessories, pet, background, effects). Name it, **save**, **reset**, **randomize**, keep up to six characters, switch between them, mark a favorite, delete. Six styles: cute cartoon, modern 2D, 3D, fantasy, animal, robot (original SVG artwork, `public/js/avatar/render.js`).
* **LEXIO TOKENS**: earned by learning, separate from XP, never sold. The ledger (`token_transactions`) has one row per achievement (`UNIQUE(user, ref)`), the balance (`token_wallets`, `CHECK balance >= 0`) is changed in the same transaction. Rewards (administrator-configurable, `Admin → Avatar → Token rewards`): lesson 10, topic 30, test 20, daily mission 15, 7-day streak 50, level 100. Paid only after a real completion (a lesson attempt that finished; a test only when passed), once per lesson / topic / test / level / streak run / mission and day. Hook: `server/lib/attempts.js → avatar.onLearning`; missions finished by other activities are paid when the missions page or any page chip (`/api/me/stats`, throttled to once per 45 s per account) is read.
* **Avatar Shop** (`/avatar/shop`): 125 items in four categories (clothing, accessories, pets & companions, special items), each with a picture, name, price, rarity (common … legendary), ownership status, **Buy** and a try-on preview. Purchases are validated on the server (`server/lib/avatar.js → buy`): item active and for sale, not owned, enough tokens, no negative balance, no double purchase (also under simultaneous requests).
* **Inventory** (`/avatar/inventory`): everything owned; equip clothing, remove accessories, change pet / pose / name, switch backgrounds, preview combinations, save. Purchased items stay on the account permanently (an owned item can only be disabled by an administrator, never deleted).
* **Pets**: one companion next to the character with a name, three poses (sit, play, sleep) and idle animations; some pets are **earned by achievements** (rules such as `lessons:25`, `streak:14`, `levels:1`, `xp:3000`, `words:100`) instead of bought.
* **Daily missions** (`/avatar/missions`): complete 2 lessons, learn 10 new words, pass a vocabulary test, practice listening, complete a speaking activity, keep the learning streak; each pays tokens once a day; 13 badges.
* **Profile**: the character card with name, outfit, companion, tokens earned, XP, achievements and character level (grows with XP: `level = 1 + floor(sqrt(xp / 40))`).
* **Reward animation**: when tokens are earned, any page shows coins and a banner once (the server remembers it was shown); the token chip sits next to XP.

## Admin (`/admin/avatar`, administrators)
Items (add / edit / delete when nobody owns it / disable, price, rarity, colours, pattern, variant, **image upload**, earn rule), token rewards, the token ledger with a user filter, and a user's purchased items with an administrator gift of tokens (audited). Editors can manage items but not rewards or the ledger.

## API
`GET /api/avatar/bootstrap`, `POST|PUT|DELETE /api/avatar/avatars[/:id]`, `POST /api/avatar/avatars/:id/activate`, `POST /api/avatar/shop/:slug/buy`, `GET /api/avatar/wallet`, `POST /api/avatar/wallet/seen`, `GET /api/avatar/missions`, `GET /api/avatar/card`; admin under `/api/admin/avatar/…`. Tables: migration `011_avatar.sql`. Catalogue: `server/seed/avatar/catalog.js`.

## Limits
Pictures are drawn from parameters (an uploaded transparent PNG, 240×340 canvas, can replace the drawing of an item); there are no real-money purchases; token rewards for review-only activity may arrive up to a minute late.
Tests: `tests/api/avatar.test.js`, `tests/ui/avatar.ui.js`.

## Fashion collections (global wardrobe)

The shop holds twelve collections, each with sub-collections: **everyday**, **traditional** (Uzbek, Japanese, Korean, Chinese, Indian, Arab, African, European), **sports**, **formal**, **fantasy**, **historical**, **futuristic**, **gaming**, **fandom-inspired**, **seasonal** (winter, summer, spring, autumn, Halloween, Christmas, Nowruz, party), **streetwear** and **luxury**. Every item has a collection and a sub-collection; the shop and the fitting room filter by them (plus search, type, rarity and ownership), and the collections only appear where items have them.

- **How items are drawn.** Clothes are not images: `public/js/avatar/outfits.js` builds an outfit from a design preset (`art.v`, ~120 presets such as `chapan`, `kimono`, `jersey_fb`, `knight_armor`, `cyber_jacket`), three colours (`c`, `c2`, `c3`), a pattern (`p`), an emblem (`e`) and a number (`n`). Hats, shoes, neckwear and capes use `public/js/avatar/wear.js` (kinds `headwear`, `footwear`, `neckwear`, `cape`). Everything is original artwork inspired by real clothing traditions, sports, eras and genres: no logos, no copied characters, and nothing explicit.
- **Body types.** A character has a body type (slim, regular, broad, `look.build`); the body, clothes and shoes follow it. The fitting room can preview an outfit on every body type. Items that cannot fit a model (hats on the animal style, glasses on the robot) are never drawn wrongly (`fitsStyle`).
- **Seed.** `server/seed/avatar/fashion.js` generates ~450 items (names in uz / ru / en built from a colour and a garment). It is added once to existing shops (`seeded_avatar_fashion_3`) and tags the first catalogue with its collections; items an administrator adds or edits are never touched. Migration `013_fashion.sql` adds `collection` and `subcollection`.
- **Growing the collection.** Admin → Avatar → Items: choose the kind (Outfit, Headwear, Footwear, Neckwear, Cape), a design (preset), the colours, pattern, emblem and number, the collection and sub-collection, price and rarity. New items appear in the shop at once. Sub-collections are free text (lowercase latin letters and hyphens) and are translated through `av.sub.<name>` when a translation exists.

## Gaming skins (game-inspired collections)

The **Game skins** tab of the shop has one category per game, each with its own sub-categories: Counter-Strike 1.6 (counter-terrorist squad, raiders, special air service style, urban response, arctic, Phoenix-style guerrillas), Counter-Strike 2 (agents, special forces, gloves, masks, military), Minecraft (explorers, creatures, Nether, diamond), Fortnite (warriors, futuristic heroes, astronauts, ninjas, fantasy characters), PUBG (military, helmets, tactical, masks, costumes), Roblox (block outfits, accessories, themed), Valorant (agents, tactical wear, accessories), Free Fire (battle, futuristic, masks, streetwear), Call of Duty (soldiers, equipment, operators), Apex Legends (sci-fi warriors, armor, character costumes), Overwatch (heroes, suits, accessories), League of Legends (champions, mages, warriors), Dota 2 (heroes, armor, robes, magic accessories), Terraria (armor sets, fantasy costumes, adventure) and Among Us (crew suits, hats, funny accessories). About 490 skins: full outfits, helmets and hats, masks and visors (`facewear`), gloves (`gloves`, slot `hands`), boots, packs and capes, neck pieces.

- **Original designs.** Every skin is drawn from scratch (`outfits.js`, `gear.js`) to hint at the genre and mood of a game: tactical vests and helmets, blocky pixel suits and cube heads, neon visors, space-crew capsule suits and funny hats, fantasy armor and robes. Nothing is copied from the games: no logos, no character or faction names, no exact outfits, no weapons. The game titles only say which game a collection is inspired by, and the shop says that the designs are fan-inspired and not affiliated with the game makers. A test keeps trademarked names out of item names.
- **Rarity.** Common, Uncommon, Rare, Epic, Legendary and **Mythic** (new, with an animated badge). Every game has at least one mythic flagship skin.
- **Shopping.** Search, sort (featured, price either way, rarity either way, name), filters by game, sub-category, type (outfit, headwear, face mask, gloves, footwear, ...), rarity and ownership, "show more" paging, Try On with turning, body types and combining pieces, and purchase with LEXIO TOKENS, all as for the other clothes. The tab is responsive and the filter rows scroll sideways on phones.
- **Admin.** Admin → Avatar → Items: the collection list includes the fifteen games; choose the kind (outfit, headwear, face mask, gloves, footwear, neckwear, cape), the design preset, three colours, pattern, emblem, number (face for the blocky heads), the game and sub-category, price and rarity. Skins can be edited, disabled (owners keep them) and removed (if nobody owns them). The seed (`seeded_avatar_games_4`) runs once and never touches items an administrator changed.

## 3D skin preview

Clicking a game skin (Game skins tab) opens a large real-time **3D preview** (`public/js/avatar/viewer3d.js`, WebGL through three.js, vendored in `public/vendor/three/` with its MIT licence and loaded only when a preview is opened):

- **The model.** The learner's own character, head to toe, wearing the skin. It is built from the skin's own design: every shape of the front picture and of the back picture (`renderAvatar` with `view: 'back'`) is extruded into a solid piece (big pieces grow back to the middle plane, so the body is a solid volume), stacked in drawing order, lit with a key / rim / fill light and shaded, standing on a glowing floor. Every colour, pattern, helmet, mask, glove and boot of the skin shows in 3D, and the model is rebuilt for each skin. It is a relief-style model built from the drawing, not a sculpted mesh.
- **Controls.** Drag (mouse or finger) to turn it round and tilt it a little; mouse wheel, pinch or the + / − buttons to zoom; Front / Side / Back buttons glide to a view; ◀ Turn / Turn ▶ turn in steps; Reset view; previous / next skin of the filtered list without closing the preview.
- **Details and buttons.** Skin name, game, sub-category, type, rarity badge and token price (or "owned"); **Try On** (opens the fitting room with the skin), **Buy** (confirmation, tokens) and **Equip** (for owned skins). Items that cannot fit the character's model are marked.
- **Without WebGL** (or if the 3D library cannot load) a turning 2.5D picture with the same views, zoom and buttons is shown (`data-mode="fallback"`).
